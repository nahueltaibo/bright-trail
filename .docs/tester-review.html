BrightTrail — Tester Review

Report a broken item from the app, and turn reports into GitHub issues · MVP · Draft v0.4 · 2026-11-16

Anyone taps the flag on an item. The app captures the item view and the details needed to replay it, shows one optional comment box, and queues the report. Reports upload when online to a Cloudflare Worker, which keeps records in D1 and captures in a private R2 bucket. A CLI and a small admin page list and triage reports. The CLI files GitHub issues with gh.

1. Flow

  1. The child or parent taps the flag (FlagButton) on an item, minigame, or story card.
  2. The app captures the item view, then opens a sheet with one optional comment box and Send.
  3. Send writes the local flags row, as today, and queues the report. Closing the sheet drops it.
  4. syncFeedback() uploads queued reports when online.
  5. An admin or AI agent runs npm run feedback:triage to pull, group, reject, and file issues. The admin page lists and triages the same reports.

2. Report

shared/src/feedback.ts holds the Zod schema. The app, the Worker, and the CLI import it.

Report {
  id: uuid                        // client-made, so a retry doesn't duplicate
  createdAt: ISO time
  comment: string | null          // up to 500 chars
  target: { contentKind: 'item' | 'card', contentId, cardIndex | null }
  item: Item | null               // the item as shown, including game and scene
  skillId
  phase                           // placement, check, review, or probe
  content: { bundleVersion, coreHash, contentSchemaVersion }
  app: { appVersion, runtimeVersion, updateId | null }
  device: { platform, osVersion, model }
  screen: { width, height, scale, fontScale }
  settings: { readingMode, dyslexicFont }
  hasCapture: boolean
}

item is a snapshot, so a report still replays after the item regenerates. The device keeps queued reports in a new reports table, with the capture as base64 text, and deletes each row once it uploads.

3. Backend

A Cloudflare Worker, with D1 for reports and a private R2 bucket for captures. The content packs already live on R2, the free tier covers this load, and no secret goes on the device. A GitHub token in the app would be extractable from the APK.

RouteDoes
POST /v1/reportsMultipart: report JSON and an optional capture file. Open to any device.
GET /admin/reportsLists reports by status, item, skill, or date.
PATCH /admin/reportsSets status (new, filed, rejected), group, and issue number.
GET /admin/captures/:idStreams a capture, or returns a signed link that expires in 7 days.

The intake route is public and unauthenticated, so it keeps these guards:

  • 30 reports per IP per hour, through the Workers rate-limiting binding.
  • JSON up to 32 KB. Capture up to 400 KB, PNG or JPEG, checked by magic bytes.
  • At most 5,000 reports and 500 MB of captures per day. Past either, it answers 503 and the app keeps its queue.
  • The Zod schema rejects anything else.

/admin/* checks the bearer secret FEEDBACK_ADMIN_TOKEN, kept as a Worker secret and in the admin's .env. The admin page is static assets on the same Worker: free, one deploy, and no CORS.

4. Privacy

  • No name, birthdate, avatar, child id, or device id in a report.
  • The capture wraps only the session body, inside SafeAreaView, so it shows app content and no system UI.
  • The repo is public. Before filing, the CLI scrubs comments of emails, phone numbers, postal codes, URLs, and long digit runs. Issues link captures with expiring links and never embed them.
  • Captures are deleted 90 days after their issue closes, or 180 days after upload if never filed.

5. Triage

The CLI lives in a new feedback/ workspace and reads FEEDBACK_URL and FEEDBACK_ADMIN_TOKEN from .env.

  • pull downloads new reports and captures to feedback/inbox/ (gitignored).
  • group groups them by item id.
  • file creates one issue per group, labeled feedback and content or app, with scrubbed comments, capture links, and the report JSON. It then marks the reports filed.

Content fixes go through a ContentEdit in content/src/generate/edits.ts, or the game's scene file, then npm run content:packs. App fixes ship as an OTA update.
