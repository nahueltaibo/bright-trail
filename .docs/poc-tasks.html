BrightTrail — POC Tasks

High-level tasks to build and run the POC · Draft v0.1 · 2026-11-06 · Delivers the POC requirements

C1 can start right away. The rest of the two tracks run in parallel once the schemas exist: content (scripts on your computer) and app (Expo). They meet when the app loads the real bundle. Size is relative effort: S, M, or L.

1. Foundation

TaskWhatDone whenSize
T1 Repo setup
#1		Folders for app/ (Expo, TypeScript), content/ (Node build scripts), and shared/ (types). Lint, format, test runner.The app starts on a phone through Expo, and a script in content/ runs.S
T2 Shared schemas
#3		Types and runtime validation (e.g. Zod) for skill, story nugget, the three item types, attempt, and mastery state.Both tracks import the same types. A sample bundle with 3 skills passes validation.S

2. Content track

TaskWhatDone whenSize
C1 Curriculum sources
#2		Collect Ontario Math 2020 Strand B text for Grades 1–6, and the number expectations from the Kindergarten Program. Save as text in the repo.One source file per grade, with expectation codes kept.S
C2 Skill graph build
#4		Script: LLM splits expectations into skills, proposes prerequisites, and a second model reviews. Detect cycles and orphans in code.skills.json with about 80 skills, no cycles, every skill reachable from a Kindergarten root. You've skimmed it.M
C3 Content generation
#5		Script: per skill, one story nugget of 5–8 cards and 15 items across the three types. Grade-aware tone. Resumable, so a failed skill reruns alone.Every skill has its nugget and 15 items in the bundle.M
C4 Validators
#6		Schema check, math answer solver, reading-level check, second-model review. Failures go back to C3 with the reason.The bundle passes all checks. A report lists any skill that needed a rerun.M

3. App track

TaskWhatDone whenSize
A1 Learner engine
#7		Pure TypeScript, no UI: mastery states, unlock rule, assumed mastery, 4-of-5 pass rule, walk-back, review at 2 days and 1 week.Unit tests cover each state change in the session diagram, including a walk-back two levels deep.M
A2 App shell and storage
#8		Navigation, profile picker by avatar, SQLite tables for children, mastery, attempts, and flags.Profiles and attempts survive an app restart.M
A3 Narration
#9		Wrapper over expo-speech: read card, read question and choices, replay button, reading-mode toggle per child.Every screen reads itself aloud, and reading mode silences it.S
A4 Nugget and item screens
#10		Story card viewer. Tap-the-answer, number keypad, and number-line drag. Feedback with a short "why". Flag button on each.All three item types work with sample content on phone and tablet.L
A5 Placement
#11		Adaptive probe: start at the derived grade, step down on misses, mark lower skills assumed. Can pause and resume.Simulated answer patterns for a Grade 1 and a Grade 5 kid give sensible skill maps.M
A6 Session flow
#12		Wire engine and screens: review first, then next gap, nugget, check. 10-minute cap. Trail map with stars.A full session runs end to end with sample content.M
A7 Parent screen
#13		PIN gate. Add child with birthdate and grade override. Skill tree by state, placement list, flagged items, JSON export, reset.A parent can set up both kids and export a log without help.M

4. Integrate and run

TaskWhatDone whenSize
I1 Load real bundle
#14		Swap sample content for the generated bundle. Check load time and app size.All 80 skills are playable, and the app opens in under 3 seconds.S
I2 Install on devices
#15		Expo development build on each family phone or tablet.Both kids' devices run the app with no computer attached.S
R1 Dry run and fixes
#16		Both parents play as each kid and miss answers on purpose to trigger walk-back. Fix what breaks.No blocking bugs. Walk-back triggers as designed.M
R2 Three-week test
#17		Week 1 with a parent watching, weeks 2–3 alone, with daily notes. Fix flagged content in the bundle as it comes up.3 weeks of logs for both kids.L
R3 Score and decide
#18		Small script reads the exported logs and scores each pass bar. Parents add their notes.A one-page result with a continue, change, or stop decision.S
The riskiest tasks are A4 (three interactive item types that must feel good to a 6-year-old) and C3 (content quality without educators). Start them early. A rough A4 prototype with hard-coded questions, shown to the kids, is worth doing before the rest of the app.
