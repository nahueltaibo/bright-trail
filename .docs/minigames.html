BrightTrail — Minigames

Which items play as minigames, which don't, and what is left to build · Draft v0.7 · 2026-11-15

513 of the 795 math items in the bundle (65%) play as a minigame. The other 282 (35%) use the plain tap, keypad, or number-line screen. The foundation, the five planned games, the ordinal line-up, and the fraction wall are built. What remains is tagging more items. The three card games play 36 of the 285 science, social studies, and health items. This page counts math items unless it says otherwise.

Why they have no game

The candidate filters, not the LLM, leave out most items. 311 of the 358 never reached their group's tagger. Only 47 reached it and got turned down. npm run content:coverage replays every tagger from the LLM cache and prints the counts per skill. Add --why to list each turned-down item with its reason, or --kind <kind> for one tagger.

The earlier estimates counted these items as fits, so each game tagged far fewer than its estimate.

The LLM's declines hold up on a sample. "How many more does Ben have", "6.3 needs more than 2 grids", "thirds can't be shown on a grid", and "second greatest" are all outside what the scene can show. join plays + 0, - 0, and a part set aside from two frames, which covers 6 items: four + 0 or - 0 items and two parts past 10.

Some cached calls no longer match today's bundle or prompts:

  • Each game was first tagged before the later games existed, so the replay runs the taggers in bundle order. On today's bundle, join's candidates differ in 10 skills, so rerunning content:join makes new calls.
  • The slices call for g1-compare-unit-fractions misses, so 9 of its candidates have no answer.
  • The hops calls for g3-mult-div-facts-2-5-10 and g3-mult-div-properties miss, so 2 candidates have no path.

3. Foundation

Done. A new game now adds files instead of touching the item schema, ItemView, and the bundle check.

StepStatusWhat landed
One game fieldDoneitem.game replaced scene, slices, and join. It is a union on kind. GAMES in shared/src/game.ts holds each game's { schema, problems }, and check-bundle.ts calls gameProblems. The change bumped schemaVersion to 2. It is 5 now. No item lost a minigame.
App registryDoneGAME_VIEWS in app/src/learning/games.tsx maps each kind to a title, a view, and demo items. ItemView renders GameView for any item with a game. /dev/games/[kind] plays each game's demo items. The per-game dev pages are gone.
One taggerDonenpm run content:games -- --kind <kind> runs a module from content/src/games/registry.ts. Each module has candidates, request, accept, apply, and a reviewed file such as content/join.json. LLM cache keys did not change. The old scripts (content:scenes, content:join, and the rest) are aliases.
